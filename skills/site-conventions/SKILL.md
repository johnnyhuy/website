# Site Conventions

The design language of johnnyhuy.com: minimal industrial. Think pi.dev and entire.io, not rounded AI-startup cards.

## Visual Rules

- **Sharp corners everywhere.** No `rounded-*` except the hero portrait (`rounded-full`).
- **Hairlines, not cards.** Separate sections with `border-b`, never shadows or elevated cards. The only shadow-like accent allowed is a 1px border.
- **One accent color.** Yellow (`yellow-500`) only: the nav square, link underlines (`decoration-yellow-500 underline-offset-4`), step icons, focus outlines. Everything else is the gray scale.
- **Mono micro-labels.** Use the `.mono-label` class (IBM Plex Mono, uppercase, tracking-wide, gray-500) for metadata, section labels, dates, and captions.
- **Borders use `var(--color-border)`.** Never hardcode gray border colors; dark mode depends on the variable.

## Layout Shell

Every page renders inside the single column shell in `app/layout.tsx` (`max-w-3xl border-x`, sticky nav inside it). Do not add your own `max-w-*`, `border-x`, or fixed navbar offsets (`pt-14` etc.) in pages. Page content is a stack of sections with `px-6` and `border-b` dividers.

## Components and Patterns

- `components/post-list.tsx` - the only post list row style (ISO date, tag icon, title).
- `components/hero-pattern.tsx` - geometric header band, picked deterministically from a seed (usually the post slug). Used in post headers; home uses `components/cloud-pattern.tsx` instead.
- `components/hero-pattern.tsx` and cloud bands always sit behind content with `opacity-25` and a `[mask-image:linear-gradient(to_bottom,black,transparent)]` fade.
- Numbered headings (`### 1. Title`) automatically render a boxed step icon via the h3 override in `components/mdx-components.tsx`. Write step sections as plain numbered h3s; do not hand-build icon markup.
- Mermaid blocks render via `components/mermaid-diagram.tsx` with the site's gray + mono theme in both modes. Use `flowchart LR/TD` with short node labels.
- Tables style themselves (mono uppercase header, hairline rows). Just write markdown tables.

## Blog Content Formatting

- **Key:value pairs go in bullet lists.** Never a run of `**Key:** value` paragraphs; make it a `- **Key:** value` list (see the repo's natural-writing convention).
- **Images**: put files in `public/images/blog/`, reference with markdown image syntax, and put an italic caption with source and license on the next line. Captions style automatically (`div:has(> img) + p`). Only use images with a clear license (Wikimedia Commons CC/PD preferred) and attribute author + license.
- **No em-dashes**, no bold-as-speech. These are enforced by past convention PRs.

## Accessibility Baseline

Do not regress these: visible focus outlines (yellow), skip-to-content link in `app/layout.tsx`, `aria-current` on nav, decorative SVGs `aria-hidden`, `BlogPosting` microdata on post pages.

## Generated Artifacts

`/llms.txt`, `/blog/<slug>.md`, sitemap, robots.txt, and feed.xml are generated by postbuild scripts in `scripts/`. Never hand-edit the generated output; edit the generator.
